# 第一次使用 NetLite

本教程以**飞牛 NAS 上的 Jellyfin** 为例，解释从域名到 HTTPS 反向代理的完整配置。若仅使用 DDNS 或证书管理，可以跳过代理步骤。

> **注意：** NetLite 当前仍处于开发与测试阶段，尤其是 fnOS 的统一网关与 Socket 权限尚待实机验收。请先在测试环境体验。以下是配置示例，不表示这些公网场景已经完成实测。

## 1. 准备工作

本示例假设：

| 项目 | 示例值 |
| --- | --- |
| NAS 内网地址 | `192.168.1.10` |
| Jellyfin 服务 | `http://192.168.1.10:8096` |
| 准备使用的域名 | `jellyfin.example.com` |
| NetLite 在 NAS 上监听的 HTTPS 端口 | `8443` |
| 期望的公网入口 | `https://jellyfin.example.com`（公网 TCP 443） |

`example.com` 是文档示例域名，不能直接拿来申请证书。请使用自己可控制解析的真实域名。

**VPS 首次管理面板访问：** Docker `host` 模式默认监听 `0.0.0.0:18780`，在服务器安全组允许指定来源 IP 后可以直接打开 `http://服务器IP:18780`，无需 SSH 隧道。通过服务器上的 `docker compose -f compose.host.yaml exec --user 10001:10001 netlite /opt/netlite/bin/netlite info --data /data` 取得初始化码。初次使用 HTTP 时密码和初始化码可能被截获，请限制访问来源并使用可信网络；申请正式证书后到「面板设置」切换为 `https://管理域名:18780`。参见 [Docker VPS 部署](DOCKER.md)。

开始前，确认：NAS 上的 Jellyfin 在局域网内可以访问；你能修改域名的 DNS 记录；家庭路由器有可用的公网入站连接，并允许做端口映射。**如果运营商使用 CGNAT 或入站连接被封锁，DDNS 并不能解决公网访问问题，NetLite 也不是内网穿透工具。**

使用 Linux VPS 时一般不需要家庭路由器映射，但仍要放行安全组/防火墙；原生 Linux 或 Docker `host` 在具备权限、端口未被占用时可直接监听 443。

## 2. 添加 DNS 账号（使用 DDNS 或 DNS-01 时）

在 NetLite 的 **「DNS 账号」** 页面选择服务商，填写 API 凭据。目前支持 Cloudflare、DNSPod.cn、腾讯云 DNSPod、阿里云 DNS。

- **DDNS：** 需要查询域名、查询记录及创建/更新 A/AAAA 的权限。
- **DNS-01 证书：** 需要读取域名/TXT、创建和删除 TXT 记录的权限。使用 DNS 验证委派时，权限应覆盖实际目标 zone。
- 不需要给账号比上述操作更多的权限；具体接口和限制见 [DNS 账号说明](DNS-ACCOUNTS.md)。

如果 DNS 已有固定公网 IP，并且证书使用 HTTP-01，可跳过 NetLite DNS 账号。

## 3. 按需配置 DDNS

如果家庭公网地址可能变化，在 **「动态域名」** 创建任务：

1. 选择 DNS 账号，填写需要更新的域名。
2. 按需配置 IPv4 / IPv6 和获取当前公网 IP 的 HTTP(S) 地址。
3. 设置检查间隔并启用，确认任务状态或历史显示同步成功。

NetLite 更新的是域名的 A/AAAA 记录；**记录更新成功不代表外网已能连接到 NAS**。若公网地址固定，也可以自行在 DNS 服务商处创建记录而不使用 DDNS。

详见 [DDNS 更新机制](DDNS-INTEGRATION.md)。

## 4. 申请 HTTPS 证书

进入 **「HTTPS 证书」**，添加 `jellyfin.example.com`，选择验证方式并填写联系邮箱。建议优先在 Let's Encrypt **测试环境**检查配置，确认成功后再申请正式环境的证书；测试证书不能像正式证书那样被浏览器直接信任。

| 验证方式 | 适合什么情况 | 必须满足 |
| --- | --- | --- |
| **DNS-01** | 泛域名（`*.example.com`）或无法开放公网 80 | 支持的 DNS 账号、所需 TXT 权限、DNS 传播正常 |
| **HTTP-01** | 单个普通域名且公网 80 可用 | 公网 TCP 80 转发至 NetLite **专用验证端口 18082**（不是管理端口 18780） |
| **内部 CA** | 局域网或测试 | 访问设备需自行安装并信任内部根证书 |

保存证书策略后，后台会自动申请。待证书状态为**可用**再创建 HTTPS 代理。DNS-01 不要求为了证书验证开放公网 80；HTTP-01 不支持泛域名。

详见 [HTTPS 证书说明](CERTIFICATES.md)。

## 5. 配置反向代理

在 **「反向代理」** 中新增规则，参考以下字段：

| 字段 | 示例 |
| --- | --- |
| 访问域名 | `jellyfin.example.com` |
| 入口 | HTTPS，端口 `8443` |
| HTTPS 证书 | 第 4 步签发且覆盖该域名的证书 |
| 目标协议 | HTTP |
| 目标地址和端口 | `192.168.1.10:8096` |

先点击**「测试目标连接」**，确认 NetLite 能访问 Jellyfin；再点击**「保存并应用」**。保存草稿不等于代理已经生效，应用成功也不等于公网可达。

fnOS FPK 不接管系统 Web 服务，业务监听端口仅使用 `1024–65535`。这里选 `8443`，是为了避免与 NAS 的 80/443 系统 Web 入口冲突。

## 6. 配置公网入口并检查

若 NetLite 运行在本示例的家庭 NAS 上，路由器可以按下面方式映射：

~~~text
外部浏览器 https://jellyfin.example.com
           ↓ DNS A/AAAA → 可到达的公网地址
公网 TCP 443 → 路由器转发到 NAS 192.168.1.10:8443
           ↓
NetLite HTTPS 代理 → http://192.168.1.10:8096
~~~

检查域名解析、端口映射、防火墙和证书状态。建议**关闭手机 Wi-Fi，用移动网络**验证域名访问，以免局域网的 NAT 回环行为干扰判断。

- **DNS 记录**指向公网可到达的地址。
- **路由器映射**为公网 TCP 443 → NAS TCP 8443；NAS 防火墙也需允许业务入口。
- **证书**覆盖访问域名且已就绪；证书测试环境和内部 CA 可能触发不受信任提示。
- **后端服务**仍可从 NetLite 所在设备到达。

Linux / VPS `host` 部署若直接监听 TCP 443，则无需“公网 443 → 本机 8443”这个路由器步骤，但仍需要放行公网 443。Docker `bridge` 部署则还需要匹配 Compose 的端口映射，不能直接照搬 `host` 上游地址的含义。

## 遇到问题怎么排查？

| 现象 | 先检查 |
| --- | --- |
| DDNS 更新成功，外网仍无法访问 | 是否有公网可达地址、CGNAT/运营商限制、路由器端口映射、DNS 缓存、防火墙 |
| 证书一直签发失败 | DNS API 权限、TXT 传播、Let's Encrypt 测试/正式环境、HTTP-01 公网 80 → 18082 |
| 代理显示已监听，但网页访问失败 | 实际入口端口、路由/防火墙、域名是否解析到正确地址、目标服务是否可达 |
| 创建代理时提示端口占用 | NAS 系统 Web 服务或已有容器是否已经占用相同监听端口 |
| Docker 可以启动但访问不到目标服务 | `host` 的 `127.0.0.1` 是宿主机；`bridge` 的 `127.0.0.1` 是容器自己，需使用可达地址或共享网络 |
| FPK 装好但打不开管理界面 | fnOS 是否支持统一网关、是否使用管理员账号、网关 Unix Socket 权限；参见 [FPK 说明](FPK.md) |
| 升级后凭据或证书丢失 | 是否完整保留数据库、`dns/master.key`、证书及已应用代理快照；参见 [Docker 备份](DOCKER.md) |

**安全提示：** 请勿公开 DNS API Key、管理员初始化码或私钥。VPS host 模式默认允许远程连接；**初次 HTTP 配置阶段应以安全组/防火墙限制访问来源，并尽快启用管理 HTTPS**。升级前完整备份应用数据目录。
